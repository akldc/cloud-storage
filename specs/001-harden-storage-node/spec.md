# Feature Specification: 单节点数据服务可靠性验证与完善

**Feature Branch**: none (no branch hook configured)

**Created**: 2026-10-27

**Status**: Draft

## Current Baseline and Evidence

本节是代码与现有测试的证据清单，不等于本功能已验收。

| 生命周期 | 断线保留检查点、一次上传中有序退出 | 取消、超时、回调与销毁交错及结果未知后的恢复 |

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 安全上传与状态确认 (Priority: P1)

调用方上传完整或分段 Chunk，能区分数据已接收、已持久化和已提交。
断线或结果不确定后，可查询状态并安全决定下一步。

**Why this priority**: 错误确认或重试可能造成静默数据丢失。

**Independent Test**: 上传、断线、重启和续传；在关键持久化步骤注入失败，
逐项核对响应、磁盘状态和重启后查询结果。

**Acceptance Scenarios**:

1. **Given** 合法片段未写满 Chunk，**When** PUT 完成，**Then** 返回未提交状态和真实持久化偏移；重启后可从该偏移续传。
2. **Given** 完整数据和正确校验值，**When** 服务确认提交，**Then** HEAD 与 GET 在重启前后看到相同的完整 Chunk。
3. **Given** 提交结果无法判定，**When** 请求结束或断线，**Then** 服务不宣称明确成功或失败；调用方可经状态查询或恢复确定后续动作。
4. **Given** 同一 Chunk 的两个写入或相冲突的描述，**When** 并发请求到达，**Then** 最多一个写入被接受，已有持久化前缀不被覆盖。

---

### User Story 2 - 准确查询、读取与删除 (Priority: P1)

调用方能查询、完整下载或按单段 Range 下载 Chunk，并仅删除匹配代数的已提交数据。

**Why this priority**: 精确的读取与删除契约是以后节点对账和副本管理的基础。

**Independent Test**: 对已提交、缺失、正在写入的 Chunk 执行 HEAD、GET、Range 和 DELETE；
在下载中注入失败，核对客户端可观察的长度与终止状态。

**Acceptance Scenarios**:

1. **Given** 已提交 Chunk，**When** 全量、闭区间、开放结尾或后缀 GET，**Then** 状态、长度、范围描述及实际字节一致。
2. **Given** 越界、反向或多段 Range，**When** 请求到达，**Then** 返回范围错误，不发送伪装成完整成功的数据。
3. **Given** 不存在、代数不匹配或活动上传，**When** HEAD 或 DELETE 到达，**Then** 结果能区分这些状态；重复删除保持幂等。
4. **Given** 下载开始后发生读取错误或客户端断开，**When** 连接结束，**Then** 不足量响应不能被当作完整成功，读取资源最终释放。

---

### User Story 3 - 慢速及并发负载下稳定传输 (Priority: P1)

慢上传、慢下载或多个连接同时工作时，服务仍可处理其他请求并保持有界资源占用。

**Why this priority**: 单连接流式样例不足以证明整体背压和容量上限。

**Independent Test**: 大 Chunk、快速发送、慢客户端、慢存储及容量饱和的组合；
检查内容、响应时间、内存高水位和资源释放。

**Acceptance Scenarios**:

1. **Given** 存储速度低于上传速度，**When** 大 Chunk 持续上传，**Then** 未处理的接收数据不会随 Chunk 大小持续增长。
2. **Given** 客户端读取速度低于下载速度，**When** 大 Chunk 持续下载，**Then** 待发送数据不会随 Chunk 大小持续增长。
3. **Given** 连接或待处理工作容量已满，**When** 新请求到达，**Then** 服务及时拒绝或关闭，不阻塞其他连接；已接受操作的结果仍可查询。

---

### User Story 4 - 可预测的断开、超时与关闭 (Priority: P2)

调用方取消当前传输或服务有序停止后，能够查询已持久化进度；
后台工作不会访问已销毁对象。

**Why this priority**: 连接和后台任务的竞态可能造成悬空访问、阻塞退出或数据丢失。

**Independent Test**: 在任务排队、执行、结果回投和响应发送时断开、超时或停止服务；
重启后核对已提交和可续传状态。

**Acceptance Scenarios**:

1. **Given** 上传连接提前断开，**When** 在途工作结束，**Then** 已确认检查点可续传；断开本身不自动删除上传。
2. **Given** 客户端长时间无进展，**When** 达到空闲期限，**Then** 连接关闭；正常进行的磁盘工作不被误判为空闲。
3. **Given** 服务收到有序停止信号，**When** 在途工作完成或被安全取消，**Then** 不再接受新工作，退出后重启可查询最终状态。

### Edge Cases

- 零字节 Chunk、零长度片段、末尾偏移、请求体提前结束或超过声明长度。
- 缺失、重复、冲突或超长请求头；非法数字、ID、校验值和代数。
- 同一 Chunk 的 PUT/HEAD/GET/DELETE 交错；不同 Chunk 的多连接并发。
- 数据或元数据写入、同步、目录发布、删除移动、读取时出现短操作、空间不足或 I/O 错误。
- 响应头发出后读取失败；连接在任务排队、执行和回调时断开。
- 第二个进程共用存储根目录；过期上传和已删除数据长期占用磁盘。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 服务 MUST 保持现有 PUT、HEAD、GET、DELETE 和单段 Range 契约，并对合法、非法、缺失及冲突输入给出稳定可区分的结果。
- **FR-002**: PUT MUST 仅接受与 Chunk 描述及连续偏移一致的数据；已提交请求的重复上传按保存的描述符判定，且该幂等语义 MUST 明确说明不会验证重发请求体。
- **FR-003**: 服务 MUST 区分已接收字节、确认持久化的续传偏移和已提交可见状态；未完成或未经校验的 Chunk 不得表现为已提交。
- **FR-004**: 写入、检查点、提交和删除的关键错误路径 MUST 有明确状态语义；无法判定提交结果时 MUST 显式标记不确定，并允许通过查询及恢复收敛。
- **FR-005**: 断线及有序关闭 MUST 保留已确认的续传前缀；重启后的可续传偏移不得超过实际持久化的数据。
- **FR-006**: 同一 Chunk 的并发写入和删除 MUST 保持一致的可见顺序；错误代数不得删除或覆盖其他代数的数据。
- **FR-007**: HEAD MUST 区分已提交、不存在、可续传和活动写入冲突；GET MUST 返回与声明长度及请求范围一致的内容。
- **FR-008**: 下载中途读取失败时，客户端 MUST 能识别响应未完成；不足量数据不得被当作成功的完整 Chunk 或 Range。
- **FR-009**: 上传和下载 MUST 在声明的连接、缓冲与在途工作上限内运行；速度失配时 MUST 施加背压或明确拒绝，不得按 Chunk 大小积累用户态数据。
- **FR-010**: 连接数、待处理工作量和请求头大小 MUST 有可验证上限；达到上限时不得使其他连接的事件处理无限等待。
- **FR-011**: 断开、取消、超时和有序退出 MUST 最终释放连接与后台资源；不可安全中断的操作 MUST 完成或形成可恢复状态，不得访问已销毁对象。
- **FR-012**: 空闲超时 MUST 针对无进展连接；正常的磁盘工作与持续传输不得因单次操作时间而被错误终止。
- **FR-013**: 第二个并发服务实例 MUST 无法使用同一存储根目录对外处理请求，以免绕过进程内写入互斥。
- **FR-014**: 删除和过期上传留下的非活动数据 MUST 有可验证的回收规则；回收不得删除健康 Chunk、活动写入或未过期的可续传尝试。
- **FR-015**: 本阶段 MUST 补齐协议边界、并发交错、背压饱和、生命周期、关键持久化故障及重启恢复的可重复测试，并记录实际结果与残余风险。

### Key Entities *(include if feature involves data)*

- **Chunk**: 已提交的不可变数据和描述，包含 ID、代数、大小及校验值。
- **Upload Attempt**: 某 Chunk 的暂存写入与可续传偏移；未提交时不能作为健康 Chunk 读取。
- **Transfer Request**: 单连接的上传、查询、下载或删除操作，具有完成、断开和超时状态。
- **Storage Root**: 一个服务实例独占的本地持久化命名空间。
- **Uncertain Outcome**: 关键步骤失败后暂不能判定成功与否的状态，必须经查询或恢复收敛。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 64 MiB Chunk 的上传、下载、断线续传和重启后读取均逐字节一致；全部现有单段 Range 形式、零字节和非法范围有确定结果。
- **SC-002**: 单个 64 MiB 上传或下载的进程内存高水位相对空闲基线增长不超过 32 MiB；16 个并发慢速与正常请求混合时增长不超过 128 MiB，且成功请求的数据一致。
- **SC-003**: 达到连接或待处理工作上限时，新请求在 5 秒内被拒绝或连接关闭；已接受请求不进入无法查询的半完成状态。
- **SC-004**: 每类关键持久化步骤均有可重复的失败与重启场景；所有已确认成功操作重启后保持相同的可查询结果，未确认完成的 Chunk 均不被误认为已提交。
- **SC-005**: 至少 16 个并发请求和 10 次重复执行中，上传、读取、删除与断线交错无数据混淆或生命周期错误，相关回归测试全部通过。
- **SC-006**: 无进展连接在所配置超时阈值后的 5 秒内关闭；有进展传输和正常磁盘处理不因单次操作耗时而被误判为空闲。
- **SC-007**: 同一 root 的第二个实例在处理请求前被拒绝；过期及删除数据按公布规则释放空间，重复回收不影响健康数据。

## Assumptions

- 本阶段只针对可信环境中的单节点数据面；认证、TLS、签名、Coordinator、多副本、对象组装和新网络框架均不在范围内。
- 保持一个连接一个已知长度请求；不要求 chunked、长连接复用或多段 Range。
- “取消”是客户端断开、请求超时或服务有序停止，不新增独立取消接口。
- 重复已提交 PUT 保持描述符幂等语义；调用方负责保证重发内容与描述一致。
- 内存指标使用服务进程的驻留高水位，测试记录空闲基线、并发规模、请求大小及慢客户端条件；内核网络缓冲不计入。
- 持久化验收依据受支持的本地文件系统同步语义；突然断电的结论必须有明确故障模型和证据，不由正常重启测试推断。
